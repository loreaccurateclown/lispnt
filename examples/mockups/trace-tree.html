What this mocks, and what it maps to

  • A view container in the activity bar holding one view, "Trace". The header row is the view's title bar; the three icons are createTreeView's actions plus showCollapseAll.
  • Nodes come from the existing TraceFrame tree: one root per marked call (label = the expression, description = its line), children are frames (label = NAME(args), description = = result). Chevron state is TreeItem.collapsibleState; children are fetched lazily, so a 1,000-frame trace never builds 1,000 nodes at once.
  • A frame that threw carries !! code in the error colour and the error theme icon; the truncated case is one leaf saying how many calls were recorded before the cap.
  • The bottom line is treeView.message: the same summary the text view prints, so the two views agree.
  • Selecting a node does nothing yet; the natural next step is reveal the call's source line, which needs call-site positions the observer does not record.
