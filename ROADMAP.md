# Lispnt roadmap

Read-only diagnostic path for Common Lisp (SBCL), alongside OLIVE.

Current state and working conventions live in `HANDOFF.md`; this file is the
long-form milestone plan. Totals today: 743 tests (70 reader, 55 analyze, 293
interpreter, 49 print, 8 pipeline, 24 bindings, 48 scopes, 55 name-checks, 19
hints, 40 trace, 24 trace-cases, 9 trace-tree, 10 value-hints, 38 extension).

## Milestones

- **M1 — Reader.** Text → AST with positions. Atoms, lists, nesting, whitespace. Then comments, strings, quote shorthand.
  *Status: complete — the reader suite, 69 tests. Covers symbols, numbers, strings with escapes, lists, `#(` vector literals (as `ListNode.prefix`), `'` and `#'` quotes (both preserved as `QuoteNode` with `quoteKind`), `#\` character literals (as `atomType: "char"`: the single character taken literally with its case kept, `#\Space`/`#\Newline`/`#\Tab` by name in any case, a delimiter such as `#\(` or `#\)` as itself), line comments, nested block comments, half-open positions, `parse`/`parseAll` over a cursor factory. Verified against SBCL on disk fixtures.*
  *Deferred: backquote/unquote. A `#\` name Lispnt does not know, or a lone `#\`, stays the symbol it always was rather than gaining a reader error for syntax we do not model. `#+`/`#-` read-time conditionals are out of scope.*
- **M2 — Structural analyzer.** Diagnostics over the AST: unbalanced delimiters, stray closers, unterminated strings/comments, malformed `defun`/`let`/`lambda` shapes.
  *Status: complete — the analyze suite, 48 tests. `ReaderError` carries a stable code plus the position of the offending construct; `analyze` returns `Diagnostic[]` with learner-facing messages, recovers past each error via `reader.next()` so a bad form does not hide the rest of the file, and runs AST shape checks (`defun` name/arglist, `lambda` arglist, `let`/`let*` bindings) recursively while skipping quoted data and `#(...)` vectors.*
  *Deferred: diagnostics carry one position, not a range (M6 converts); shape checks do not validate binding entries or arity.*
- **M3 — Interpreter.** Evaluator over the AST: `defun`, `if`, `cond`, `let`, arithmetic, recursion.
  *Status: complete — the interpreter suite, 293 tests. Special forms incl. `let*`, `cond`, `when`/`unless`, `progn`, `defun`/`lambda`, `labels`/`flet`, `setq`/`setf` with places, `dolist`/`dotimes`/`do`/`do*`/`loop`/`return`, `push`/`pop`, `case`/`ecase`/`ccase`, `defstruct`; sixty-odd builtins; arrays; characters; structures; hash tables; dotted pairs; `#'` function quotes. `car` and `cdr` of `NIL` are `NIL`, as in CL — any other non-list is still a `type-error` — so a learner can walk a list without guarding every step. Evaluation errors surface as diagnostics with codes and positions, a step budget stops runaway code, and an observer exposes form and call events for M4/M5.*
  *Characters. A character is its own value kind (`{ kind: "char" }`), because CL's `character` is not a string and not a number: `(equal #\a "a")` is NIL, `(typep #\a 'character)` is T, and case is part of the value (`#\a` and `#\A` differ) while character names are case-insensitive (`#\Space` is `#\space`). It prints as SBCL does — `#\a`, `#\A`, `#\Newline`, `#\Tab` — except for the space character, which SBCL prints as `#\` plus an invisible space and Lispnt prints as `#\Space` for legibility; both read back identically. `eq` compares characters by code, which is what SBCL answers though the standard only promises `eql`. `DO`/`DO*` evaluate every initial form in the enclosing environment before binding (`DO*` binds as it goes), test at the top of each iteration, and let `RETURN` leave the loop; `CASE` matches `OTHERWISE`/`T`, single keys and key lists by `eql`, and `ECASE`/`CCASE` signal on a miss — CL's `CCASE` would offer a restart to correct the key, which Lispnt has no mechanism for. `(error "…")` throws a `signalled-error` carrying the learner's own message, and the diagnostic shows that message rather than a generic line. `TYPEP` answers a table of type specifiers (`T`, `NIL`, `NULL`, `SYMBOL`, `KEYWORD`, `NUMBER`, `INTEGER`, `RATIONAL`, `FLOAT`, `LIST`, `CONS`, `ATOM`, `ARRAY`, `VECTOR`, `STRING`, `CHARACTER`, `HASH-TABLE`, `FUNCTION`) and any structure type a `defstruct` has defined; anything else — compound specifiers such as `(integer 0 10)`, `(or …)`, a struct name nothing defines — is `unsupported-standard`, so a type system we do not model stays silent instead of answering a confident NIL. Keyword arguments exist where a builtin declares them: `COUNT` takes `:test` and `:key`, `SORT` takes `:key`, `MAKE-ARRAY` and `MAKE-STRING` take their initial-value options, and a key nothing declares is `unsupported-standard` rather than a wrong call. Numbers are JS doubles, so `INTEGER` is `Number.isInteger` and `1.0` reads as `1`.*
  *Structures. `DEFSTRUCT` is evaluated, not only checked: a structure is `{ kind: "struct"; type; slots }` with its slots in definition order. The four names CL generates are defined — the keyword constructor `MAKE-NAME` (`(make-tree-node :key 10)`; missing slots take their defaults, an unknown keyword or an odd argument count is an error), the predicate `NAME-P`, the copier `COPY-NAME` (a shallow copy), and one accessor per slot named with the conc-name. `:conc-name nil` gives the bare slot names, which is what every corpus `tree-node` relies on; the default prefix is `NAME-`. An accessor is also a place, so `(setf (lc node) …)` assigns the slot — accessors are setf-able in CL unless the slot is `:read-only`, and reporting that form as `not-a-place` would blame the learner for our gap. `:include`, other defstruct options and slot options such as `:type` are `unsupported-standard`. Structures print as `#S(NAME :SLOT value …)` with the same depth and cycle limits as lists, compare by identity (`equal` does not descend, as in CL; `equalp` here does not either, which is a known divergence), and answer `TYPEP` once their type has been defined. Structure constructors take keyword arguments through the same binder `&key` uses, added in M3-EXTRA.*
  *Loops. `LOOP` is evaluated for a deliberate subset: `(loop form…)`; `for`/`as` with `in`, `on`, `across`, and numeric `from`/`to`/`below`/`above`/`by`; `while`, `until`, `repeat`; `do`/`doing`, `collect`, `append`, `sum`, `count`, `maximize`, `minimize`, each with `into`; `initially`, `finally`, `return`; and `if`/`when`/`unless` with `else` and `end`. Any clause word outside that set — `named`, `with`, `thereis`, `always`, `never`, `nconc` — is `unsupported-standard`, never silently skipped. Drivers step in parallel and are bound before the termination test; `into` leaves the loop's value NIL unless a `finally` returns; `finally` does not run when `return` exits; clauses of the same implicit accumulation kind share one value, while two different kinds are an error — all as in SBCL. The parser also enforces CL's shape rules: a driver may not follow a main clause or sit inside a `when`/`if`/`unless` body, and `do`, `initially` and `finally` take compound forms. Every iteration charges one step, so a loop whose body evaluates nothing still trips the evaluation budget.*
  *Hash tables. A table is `{ kind: "hash"; test; entries }` with `make-hash-table` (`:test` limited to `eq`, `eql`, `equal` and `equalp`), `gethash` including as a `setf` place, `remhash`, `clrhash`, `hash-table-count`, `hash-table-p` and `maphash`, and it prints as `#<hash-table :count n>`. A key is found again through a canonical form chosen by `:test`: atoms compare by value, `eq`/`eql` compare cons, array and structure keys by identity, and `equal`/`equalp` by full printed form — so two structurally equal lists are one key under `equal` but two under `eq`, as in CL. `equalp` is treated as `equal`, since nothing in Lispnt descends into structures yet. `:size`, the rehash options, and any `:test` other than those four are `unsupported-standard`. LOOP's `being the hash-keys|hash-values of|in table [using (hash-value|hash-key v)]` walks a table in insertion order, which CL leaves unspecified.*
  *Formatting. `(format destination control args…)` implements `~a`, `~s`, `~d`, `~%`, `~~` and `~&`; `nil` returns the string and `t` returns NIL after discarding the output, because Lispnt has no console. A directive ANSI defines but Lispnt has not built — `~b`, `~x`, `~r`, `~p`, `~c`, `~t`, the iteration and justification clusters — is `unsupported-standard`, while a character that is not a directive at all (`~q`) is `malformed-form`: our gap stays silent, the learner's mistake is reported. Directive parameters and modifiers (`~5d`, `~:@a`) are `unsupported-standard`. `~a` renders princ-style — strings unquoted, characters bare, recursively inside lists — which is a `princ` option on `printValue`; `~s` uses the readable form.*
  *Streams. `with-output-to-string` binds a string output stream for its body and returns everything written to it; `write-char`, `write-string`, `princ` and `prin1` append and return their object, `princ-to-string` and `prin1-to-string` return the text, and `format` accepts a stream as its destination. With no stream argument the text is discarded, since there is no `*standard-output*` — the same divergence as `format t`. A stream prints as `#<string-output-stream>` and answers `TYPEP` for `STREAM`. The slice also fixed two sequence readers it depended on: `length` of a string was 0 because only arrays and lists were handled, and `elt` on a string returned NIL; both read characters now, which is what lets `upper-string` and `grade-letters` run.*
  *Sequences and property lists. `getf` reads a property list — pairs of indicator and value, `eql` as the test — with a default for an absent indicator, and it is a `setf` place: an existing pair is updated in place, an absent one is consed onto the front, as in CL. A property list that is not a list is a `type-error`, and one ending in a lone indicator is `malformed-form`. `sort` takes two arguments — no `:key`, no `:test` — accepts a list, a vector or a string, copies rather than mutating, so a recorded snapshot cannot change under a hint, and is stable, which CL's `sort` does not promise but does not forbid. `string<` compares string designators: a string, a symbol's name, or a character as a one-character string. Sorting a non-sequence is a `type-error`. The `gethash` place also honours its default now, which is what lets `(incf (gethash key table 0))` start from zero.*
  *Multiple values. `values` produces a bundle that never reaches a single-value context: `evaluate` takes the primary value, so `(values 1 2)` is `1` anywhere one value is expected, while `multiple-value-bind`, `multiple-value-list`, `multiple-value-setq` and the trace observer ask for all of them. Each is a special form rather than a function, since each needs its operand form unevaluated; CL has them as macros. Names the form did not provide are bound to NIL. `gethash` answers its second value — whether the key was present — and `floor` its remainder, both as CL does; a plain `(gethash k h)` or `(floor a b)` still reads as one value. The trace prints every value from a call (`F() => 1 2`), which is what SBCL's trace does.*
  *Deferred: `handler-case`, `#+`/`#-`, backquote/unquote. All are in the standard-symbols list, so they are silently skipped rather than misreported. That list is now true: the implemented names still held there — twenty-one of them, then the seven hash-table names — were removed, leaving 171 names today — a measured count, since later slices dropped their own names without correcting the 189 this sentence used to claim. For calls nothing changed, because `scopes.ts` fills the function table from `builtins` before `STANDARD_SYMBOLS`; the only visible effect is that a bare `do`, `case`, `incf`, `decf` or `defvar` used as a variable now reports `unbound-variable` instead of being dropped as our own gap. The corpus still reports the same 10 diagnostics.*

- **M3-EXTRA — Evaluator and standard-library gaps.** The work that fills in what the reader, checker and interpreter recognise but could not run. Named like M4-STATIC: a suffix on the milestone whose capability it extends, not a new layer. It exists so this plan lives in the roadmap rather than only in `HANDOFF.md`, and each item moves from Planned to Shipped when it lands.
  *Shipped, in order.* **Evaluator gaps, cheap part** — 2026-11-23, `3f3cef2`: the character value kind and the builtins and special forms built on it (`SCHAR`, `CHAR`, `CHAR=`, `CHAR-UPCASE`, `1+`, `1-`, `MAX`, `MIN`, `COUNT`, `BUTLAST`, `ERROR`, `TYPEP`; `DO`/`DO*`; the `CASE` family), plus a `signalled-error` diagnostic code that carries the learner's own message. Semantics are recorded under M3; the suite went from 484 to 522 tests. **Structures** — 2026-11-23: `DEFSTRUCT` evaluated rather than only checked — the structure value kind, keyword constructor, predicate, copier, setf-able accessors, `#S(…)` printing, identity equality and the `TYPEP` registry. This is what makes the corpus's seven `tree-node` files and `practicum2-all-topics.lisp`'s `book` trace instead of failing with `undefined-function`; 522 to 546 tests. **Standard-symbols cleanup** — 2026-11-23, `4be459b`: twenty-one implemented names removed from the silent list, 217 to 196. **LOOP, limited** — 2026-11-23: `src/core/loop.ts` parses the clause grammar and `evalLoop` runs it, with the clause set and semantics recorded under M3 and the same fail-loud rule as the rest of the evaluator. Two semantic bugs found by testing against SBCL and fixed: clauses sharing an implicit accumulator each evaluate their own form, and drivers bind before the termination test. The corpus's four loop-bearing functions now trace — both `LEVEL-ORDER`s to `(1 2 4 3)`, `AVERAGE-LIST-LOOP` to `2.5`, and `lab08-practice/q4.lisp`'s `BTREE-COLLECT-BFS` to `(1 2 3)` with defstruct underneath. During this slice the step budget turned out to be unable to stop a body-less loop, and a budget error thrown outside a pass left the shared counter above its ceiling, disabling every later evaluation; both are fixed, and 546 to 579 tests. **Hash tables** — 2026-11-23: `make-hash-table` with `:test`, `gethash` and its `setf` place, `remhash`, `clrhash`, `hash-table-count`, `hash-table-p`, and `maphash`, which is registered in the interpreter because it calls a function. LOOP gained `being the hash-keys|hash-values of|in … [using (hash-value|hash-key v)]` as a clause-table entry, so the driver cost a parser addition rather than a rewrite; key identity per `:test` is recorded under M3. The corpus's `table-sum` now traces to 3, `table-keys` to `("a" "b")` and `count-deficit-accounts` to 0, and the suite went from 579 to 590 tests. **FORMAT** — 2026-11-23: `format` with the `~a ~s ~d ~% ~~ ~&` subset, `nil` returning the string and `t` discarding, and the two-tier failure split recorded under M3; `printValue` gained a `princ` option for `~a`. `print-pairs` and `report-pair` in the corpus now trace, and 590 to 603 tests. **Output streams** — 2026-11-23: `with-output-to-string` binding a string output stream, `write-char`, `write-string`, `princ`, `prin1`, `princ-to-string`, `prin1-to-string`, `format` writing to a stream, and `typep` answering `stream`; with no stream the text is discarded. Two sequence readers it depended on were fixed: `length` and `elt` on strings. `upper-string` and `grade-letters` now trace — `"ABC"` and `"AFBA"`, where the corpus file's own comment claims `"ACBA"`; SBCL agrees with AFBA. 603 to 615 tests. **GETF, SORT, STRING<** — 2026-11-23: `getf` with a default and a `setf` place (update in place, or cons a new pair onto the front), `sort` as a two-argument, copying, stable sort over lists, vectors and strings, and `string<` over string designators. Testing this against the corpus turned up a hole from the hash slice: the `gethash` place ignored its default, so `(incf (gethash w table 0))` — the canonical build-then-query idiom in `word-counts` — read NIL; the place honours it now. `(sort (table-keys (word-counts '(a b a))) #'string<)` gives `(A B)`, `array-stats` is readable through `getf`, and 615 to 624 tests. **Multiple values** — 2026-11-23: `values`, `multiple-value-bind`, `multiple-value-list` and `multiple-value-setq`, with the primary value taken implicitly everywhere else; `gethash` answers present-p and `floor` its remainder; the trace prints every value a call returned, as SBCL's trace does. Verified against SBCL for the bundle, the present-p, the remainder and the trace line. `print-pairs-do` in the corpus still stops at `with-hash-table-iterator`, which is a separate gap, and 624 to 633 tests. **Lambda lists** — 2026-11-23: `DEFUN`, `LAMBDA`, `FLET` and `LABELS` parse `&optional`, `&rest`/`&body`, `&key` and `&aux` once at the definition and bind them on each call. An optional default and an `&aux` initialiser run in the scope of the parameters to their left, supplied-p names bind to `T` or `NIL`, `&key` matches by keyword name so `((:total sum) …)` renames it, and `&rest` keeps the same keywords `&key` reads. Fail-loud: an unimplemented marker such as `&allow-other-keys` is `unsupported-standard`; an out-of-order marker and a repeated name are `malformed-form`, which is what SBCL reports for both. Before this, a marker was silently bound as a parameter name — `(defun f (a &optional b) …)` demanded three arguments and `(f 1)` then failed inside evaluation with an arity error the checker dropped. The checker gained the half it was missing: every name a lambda list binds is a parameter binding, and defaults and `&aux` initialisers are walked as code, each in a scope holding only the parameters to its left, so `(defun f (&optional (b 1)) b)` no longer reports `B` unbound and a default naming a parameter to its right is still reported. `DEFSTRUCT` constructors now run through the same keyword binder, and a keyword that names no slot is `type-error` rather than `malformed-form` — the form is complete, the argument is wrong. Verified against SBCL for defaults, supplied-p, renaming, `&rest` with `&key`, arity, and both lambda-list errors. 633 to 656 tests. **Builtin keyword arguments** — 2026-11-24: one `parseKeywords` in `builtins.ts` backs every builtin that takes keywords: a key Lispnt does not model is `unsupported-standard`, an odd count `malformed-form`, a non-keyword in a key position `type-error`, and a repeated key keeps its first value, as SBCL does. `MAKE-ARRAY` takes `:initial-element`, `:initial-contents`, `:adjustable` and `:fill-pointer`; `MAKE-STRING` takes `:initial-element`; `MAKE-HASH-TABLE` takes `:size` and the rehash hints, which CL gives no effect a program can observe, so they are checked and ignored, and its `:test` now accepts a symbol designator as well as a function. A vector carries an optional fill pointer: `length` and printing stop at it, `aref` stays bounded by capacity, and `vector-push`/`vector-push-extend` write and advance it — a vector with no fill pointer is a `type-error`, as in SBCL. `COUNT` moved beside `SORT` because it calls a user function: it takes `:test` and `:key`, reads a string as a sequence of characters, and now defaults to EQL rather than EQUAL, which is what CL specifies and the old two-argument form got wrong. `SORT` takes `:key`, applied per comparison, which is the number of calls SBCL makes. `WITH-HASH-TABLE-ITERATOR` is a special form binding a closure over the table's entries: `(t key value)` until the table is empty, then NIL. Two older bugs fell out of the work: `(vector)` crashed the evaluator with a raw TypeError, and `MAKE-ARRAY` read `:initial-element` positionally, so any other keyword was silently misread. Six implemented names left the silent list: `WRITE-CHAR`, `SORT`, `WITH-HASH-TABLE-ITERATOR`, `MAKE-STRING`, `VECTOR-PUSH` and `VECTOR-PUSH-EXTEND`. Verified against SBCL for the keyword rules, the fill pointer, `make-string`, `:test`/`:key` and the iterator; `build-dynamic-array` now traces to `#(1 2 3)` and `print-pairs-do` to NIL, both matching SBCL, and the corpus is unchanged at 10 diagnostics. 656 to 676 tests.*
  *Planned.* Nothing further in this milestone; M6, the extension shell, is the next piece of work.
- **M4 — Value tracking.** Evaluate to a point, expose symbol values for inline display.
  *Status: complete except for the extension-side presentation and cache. Four pieces exist. `src/core/print.ts` renders a value as text the way SBCL would for the same limits — `(1 2 3)`, `(1 . 2)`, `#(1 2)`, `#<builtin CAR>`, `#<function F>`, `NIL` — with `...` for cut elements and cycles and `#` for cut depth (49 unit tests, 8 pipeline tests). `withStepCeiling` gives each pass its own ceiling under a fixed 2,000,000 backstop, so the value pass runs at 200,000 steps and an analysis pass at the backstop, with no shared mutable limit and no nesting. The counter is also scoped to the outermost evaluation when no pass is open: a budget error thrown outside a pass used to leave `steps` above the ceiling and disable every later evaluation in the process, which is how one stale test turned into twenty-six failures. `src/core/bindings.ts` runs the file and records a binding snapshot when each list form finishes, with the binding map copied; `recordBindings` returns the snapshots plus an `unavailable` code (`budget`, `truncated`, `unparsed`), and `snapshotAt` resolves an offset to the innermost snapshot containing it, falling back to the latest finished form only when the run completed (24 tests). `src/core/hints.ts` turns a run into displayable hints: `collectHints` returns `hintsForLine`, `hintsInLines` and `hintAt`, and `formatHint`/`formatLine` render `X = 5` (19 tests).*
  *How hints behave, and why. A hint exists where a name is **read** and the run has a value for it. The list of reads comes from the same scope walk the static checker uses, so function heads, binding sites, quoted data, vector contents and the bodies of unmodelled standard forms are already excluded; the value comes from the snapshot containing that use, not from the line, which is what makes a function body show the parameter of the most recent call. One hint per name per line, at its first use, in source order. The line that binds a name — `(defparameter x 5)` — produces no hint for `X`, because it is a binding site; the next line that reads it does. Names absent from the snapshot are silent, so unbound names and builtins never appear. Values are printed with `printValue` at the same limits a REPL uses (8 elements, depth 3), overridable per call and provisional until the hint line has been seen with real values in it. Hints are therefore a report on what executed, and the static checker in M4-STATIC is the report on what will run; neither pretends to be the other.*
  *Measured limits, from the 44-file corpus and awaiting user testing. Only 13 of 44 files produce any hint at all (2 to 11 lines each) once the `;;[trace]` markers run; 7 do without them, because most learner files define functions and call none of them, so no body ever runs — the same shape that motivated M4-STATIC. Inside a function that was never called, the only names with values are globals, and they show the state at definition time rather than at the line. A value read after a mutation in the same form can be stale (`incf` on the line shows the pre-increment value), because snapshots copy binding maps but not the mutable values inside them. Cost is not a concern: a full-file hint pass plus a query for every line takes about 4 ms on a 20 KB file.*
  *Rejected: a static tier for values. A constant-folding or symbolic tier was measured before building it — 35 of 77 corpus local bindings have literal values, 11 more are computable from literals, and the remaining 31 depend on inputs, while all 286 function parameters have no static value by definition. So a tier would restate what the source already says (`y = 5` beside `(let ((y 5))`), cover none of the parameters, and appear inconsistently next to hints from execution — a pattern a learner cannot explain without knowing scope and closure rules they are still learning. Values stay a runtime observation; if users later ask to see a binding's definition, that is a hover, not a per-line value.*
  *Remaining: nothing extension-side. Hints ship in M6 slice 6.5 as editor inlay hints, one run per document version, switched off by `lispnt.showValueHints`. A cursor-position mode is not needed: an inlay hint is positioned by definition, so the per-line mapping is the natural one.*
- **M4-STATIC — Static checks over the whole file.** Every form checked whether or not anything calls it: the names each scope binds, undefined functions, argument counts, a variable called as a function, unbound variables, and structural checks inside bodies.
  *Status: complete as scoped — 48 scope tests and 55 name-check tests. Slices 1–3 are done: the scope model and symbol table (`src/core/scopes.ts`), structure rules for the walk (head atoms, `cond` clauses, `function` targets, `loop` clauses), and name checks over every body (`src/core/name-checks.ts`) — undefined functions, unbound variables, wrong argument counts, a variable called as a function. `analyze` runs them after the shape checks and evaluation, and drops the evaluator's copies of those three codes. Slices 4–6 decode the standard forms whose binding syntax used to be skipped: `defstruct` (its generated constructor, predicate, copier and accessors), `do`/`do*` and the `case` family, and the binding macros (`with-output-to-string`, `with-input-from-string`, `with-open-file`, `with-open-stream`, `with-hash-table-iterator`, `multiple-value-bind`, `destructuring-bind`, `handler-case`). Exists because learner code is usually a set of `defun`s loaded and compiled in the SBCL REPL rather than called in the file: 21 of the 37 corpus files with `defun`s call none of them, and 78 of 199 corpus `defun`s are never called. Evaluation only sees code that runs, so those bodies are checked today for nothing but name and arglist shape. This is the project's pre-compile promise — finding the mistake before SBCL's debugger does. The decodings for `do`/`do*`, the `case` family and `defstruct` are now evaluated too, so those bodies trace; only the binding macros remain checker-side.*
  *Remaining opaque forms, decoded only when learner code uses them: `defclass`, `defgeneric`, `defmethod`, `defmacro`, `deftype`, `defpackage`, `with-slots`, `with-accessors`, `multiple-value-setq`, `handler-bind`, `restart-case`, `macrolet`, `symbol-macrolet`. Their bodies go unchecked and, for the definition forms, their generated names are unknown. Name checks also need the checker's own list of special forms, so that `(if …)` is not read as a call to `IF`; that list mirrors the interpreter's dispatcher, and a test asserts the two stay in step. Evaluating `loop` shipped in M3-EXTRA, so the clause bodies it decodes now run as well.*
  *Deferred: any knowledge beyond this file and the standard library (unknown names stay at most a warning); unused bindings; type inference; finishing the `loop` walk (an atom in a driver position such as `xs` in `for x in xs`, and a bare-atom body such as `do x`, are skipped — recovering them means decoding clauses rather than scanning keywords; both are lost checks, not false reports.*
- **M5 — Recursion trace.** Frame enter/exit recording, rendered as a call tree outside the REPL.
  *Status: complete in core. Slice 5.1 records: `src/core/trace.ts` (`traceCalls`, `traceFormIn`, `TraceFrame`, `TraceResult`) runs in an observer and builds a tree of the calls made. No interpreter changes were needed — `applyFunction` already fires `onCallEnter`/`onCallExit`, and builtins bypass that path, so the trace holds the learner's own functions and never `+`, `car` or `list`. Arguments and results are printed at call time rather than at render time, so a cons mutated later cannot rewrite history; a frame that threw carries `error` and no `result`, while its ancestors carry neither because they never returned. Caps: 200,000 steps (the same as the value pass), depth 64 and 1,000 frames; past a cap evaluation continues so results still complete, recording stops, and `truncated` says so. `unavailable` reports `budget` or `unparsed`; `failed` reports the code of a non-budget error that ended the run. Slice 5.2 renders: `renderTrace` writes one line per frame as `NAME(args) => result`, two spaces of indVent per level, `!! code` on the frame that threw, and `…` footers for a budget stop, a failure, or truncation. Slice 5.3 finds the calls to trace: `src/core/trace-cases.ts` (`traceCases`, `TraceCase`) scans line comments for the marker `;;[trace]` followed by one form — whitespace and case inside the brackets are tolerated, `;; [trace]` works, and a marker inside a block comment is ignored. Each marked line is an independent case: the file is re-evaluated in a fresh environment for that case, then the marked expression is traced in it, so two markers above one `defun` give two traces and one case cannot see another's mutations. Text after a marker that does not parse is reported as `unreadable` rather than silently dropped; a case whose call fails reports through the trace's own `failed`/`unavailable`. Slice 5.4 renders for a learner rather than as a step log: `renderTrace(result, options?)` labels the outermost call `root: 0:` and every entry line at the deepest level `max depth: n:`, leaves the levels between them bare, and closes with a summary line (`15 calls · max depth: 6 · final value: 5`). `TraceResult.finalValue` carries the value the run returned — the last top-level form's for a whole file, the marked form's for a case — and is omitted when the run failed. A cap or a budget stop makes the recorded depth a floor, so the label and the summary both read `(limit reached)`. The display limit this roadmap had specified is now delivered: `options.limit` (default 10) keeps the first N calls at each level plus the last one and states `… k more calls hidden`, `"all"` shows everything, and N is clamped to the 1,000-frame cap; a marker may also ask for it as `;;[trace:N]` / `;;[trace:all]`. `EXPLAIN_TRACE` is the explanation paragraph, appended only when `options.explain` is set, so the extension can style it or turn it into a setting. All four slices are 60 tests (39 trace, 21 trace-cases).*
  *Why the marker exists: learner files define functions and call none of them — a trace needs a call. On the corpus that is literal: before the repo test files carried markers, **0 of 44 files** produced a single frame; now 7 of 44 do, one marker each. Writing the call in a comment lets the learner trace a function without editing what SBCL loads, and without a REPL: `;;[trace] (fact 4)` above the definition yields `root: 0: FACT(4) => 24` with each recursive call indented beneath its caller and the deepest level labelled. Measured limits: 0.2–1.2 ms for a call like `(fact 4)`; naive `(fib 15)` is 1,973 calls and hits the 1,000-frame cap in ~7 ms; `(fib 20)` is 21,891 calls and also trips the step ceiling in ~16 ms; `(fib 30)` would be 2,692,537 calls, so the caps turn it into `truncated`/`budget` instead of a several-second stall.*
  *Not recorded: call-site positions, because the observer does not carry them and adding them would touch the evaluator's hot path for a field the tree does not need yet. Not supported: a case spanning several comment lines, and a marker that is not a line comment. Rendering is text only; a tree view, hover hints about the marker, and live updating belong to M6. A counting mode (call totals and maximum depth with no frames kept) is the answer for calls too large to record and is deferred.*
  *Deliberate difference from SBCL's layout, not a defect to fix. SBCL prints a call as an entry line, then its subtree, then a `FUNC returned value` line at the same depth, so a call and its result are two lines and the result sits below what produced it. Our renderer keeps one line per call, `NAME(args) => result`, which means the value is attached to the call that produced it rather than printed on exit: a line reads "called with these arguments; everything below it totals this". The ordering of lines is unchanged (depth-first, as recorded); what differs is that a line is a labelled subtree rather than an event in time, so completion order is not shown. Against the same `count-atoms` call on `'(a (b (c d)) e)` that is 15 lines plus a summary where SBCL needs 30. Two labels make the ends of the recursion explicit — `root: 0:` on the outermost call, `max depth: n:` on every entry line at the deepest level — because following a recursion by eye is the thing learners struggle with, and the summary line states the call count, the depth and the final value in one place. Measured divergence worth keeping in mind: SBCL cannot trace a `labels` local at all (`COUNT-SUBTREE-SINGLE-CHILDREN is undefined, not tracing`), while our recorder sees it, which is what makes the corpus tree labs traceable at all; matching SBCL's wording is therefore never the goal, only its clarity.*

## Agent working rules

The rule is one thing: **when something goes wrong, halt and explain the problem — what is known, what is not, and what would be tried next — and let the user decide how to proceed.** Everything below is a safety rail or a record of a session that failed to do that; none of them is a substitute for it.

Safety rails:

- A command with no result after three minutes is killed and reported. No third attempt at the same thing.
- A test run past about twice the baseline is a hang, not a wait. The full suite runs in a couple of seconds; a minute of it is already wrong.
- No silent investigation longer than three minutes, even mid-diagnosis.

What the rails do not cover, learned the hard way. A diagnosis once hammered the test runner for half an hour looking for a hang that one `grep loop test/` found in seconds. They measure elapsed time, not whether the next action can distinguish the remaining hypotheses — and after a while it could not:

- **Read the inputs before modelling the outputs.** When a change removes an assumption, the first thing to inspect is everything that relied on it. `(loop)` stopped being a form the evaluator skips, which invalidated a test that used `(loop)` as its example of one. That test was a suspect from the moment the change was made, not a victim found later.
- **A result that invalidates the method is not a data point.** When a test that does nothing but `evaluate(parse("42"))` hung, no amount of bisecting by test name could localise anything. That was the point to stop and ask, not to gather another data point.
- **More process is not a fix.** Rules about minutes and hypothesis counts create the feeling that a class of problem has been handled, which is how the same circling gets licensed again under a different heading. The rails above are for stopping runaway commands; judgement is the halt-and-explain rule at the top.
