# Lispnt roadmap

Read-only diagnostic path for Common Lisp (SBCL), alongside OLIVE.

Current state and working conventions live in `HANDOFF.md`; this file is the
long-form milestone plan. Totals today: 522 tests (69 reader, 48 analyze, 157
interpreter, 42 print, 8 pipeline, 24 bindings, 44 scopes, 51 name-checks, 19
hints, 39 trace, 21 trace-cases).

## Milestones

- **M1 — Reader.** Text → AST with positions. Atoms, lists, nesting, whitespace. Then comments, strings, quote shorthand.
  *Status: complete — the reader suite, 69 tests. Covers symbols, numbers, strings with escapes, lists, `#(` vector literals (as `ListNode.prefix`), `'` and `#'` quotes (both preserved as `QuoteNode` with `quoteKind`), `#\` character literals (as `atomType: "char"`: the single character taken literally with its case kept, `#\Space`/`#\Newline`/`#\Tab` by name in any case, a delimiter such as `#\(` or `#\)` as itself), line comments, nested block comments, half-open positions, `parse`/`parseAll` over a cursor factory. Verified against SBCL on disk fixtures.*
  *Deferred: backquote/unquote. A `#\` name Lispnt does not know, or a lone `#\`, stays the symbol it always was rather than gaining a reader error for syntax we do not model. `#+`/`#-` read-time conditionals are out of scope.*
- **M2 — Structural analyzer.** Diagnostics over the AST: unbalanced delimiters, stray closers, unterminated strings/comments, malformed `defun`/`let`/`lambda` shapes.
  *Status: complete — the analyze suite, 48 tests. `ReaderError` carries a stable code plus the position of the offending construct; `analyze` returns `Diagnostic[]` with learner-facing messages, recovers past each error via `reader.next()` so a bad form does not hide the rest of the file, and runs AST shape checks (`defun` name/arglist, `lambda` arglist, `let`/`let*` bindings) recursively while skipping quoted data and `#(...)` vectors.*
  *Deferred: diagnostics carry one position, not a range (M6 converts); shape checks do not validate binding entries or arity.*
- **M3 — Interpreter.** Evaluator over the AST: `defun`, `if`, `cond`, `let`, arithmetic, recursion.
  *Status: complete — the interpreter suite, 157 tests. Special forms incl. `let*`, `cond`, `when`/`unless`, `progn`, `defun`/`lambda`, `labels`/`flet`, `setq`/`setf` with places, `dolist`/`dotimes`/`do`/`do*`/`return`, `push`/`pop`, `case`/`ecase`/`ccase`; fifty-odd builtins; arrays; characters; dotted pairs; `#'` function quotes. Evaluation errors surface as diagnostics with codes and positions, a step budget stops runaway code, and an observer exposes form and call events for M4/M5.*
  *Characters and the evaluator-gap slice. A character is its own value kind (`{ kind: "char" }`), because CL's `character` is not a string and not a number: `(equal #\a "a")` is NIL, `(typep #\a 'character)` is T, and case is part of the value (`#\a` and `#\A` differ) while character names are case-insensitive (`#\Space` is `#\space`). It prints as SBCL does — `#\a`, `#\A`, `#\Newline`, `#\Tab` — except for the space character, which SBCL prints as `#\` plus an invisible space and Lispnt prints as `#\Space` for legibility; both read back identically. `eq` compares characters by code, which is what SBCL answers though the standard only promises `eql`. Builtins added with it: `SCHAR`, `CHAR`, `CHAR=`, `CHAR-UPCASE`, `1+`, `1-`, `MAX`, `MIN`, `COUNT`, `BUTLAST`, `ERROR` and `TYPEP`. `DO`/`DO*` evaluate every initial form in the enclosing environment before binding (`DO*` binds as it goes), test at the top of each iteration, and let `RETURN` leave the loop; `CASE` matches `OTHERWISE`/`T`, single keys and key lists by `eql`, and `ECASE`/`CCASE` signal on a miss — CL's `CCASE` would offer a restart to correct the key, which Lispnt has no mechanism for. `(error "…")` throws a `signalled-error` carrying the learner's own message, and the diagnostic shows that message rather than a generic line. `TYPEP` answers a table of type specifiers (`T`, `NIL`, `NULL`, `SYMBOL`, `KEYWORD`, `NUMBER`, `INTEGER`, `RATIONAL`, `FLOAT`, `LIST`, `CONS`, `ATOM`, `ARRAY`, `VECTOR`, `STRING`, `CHARACTER`, `FUNCTION`) and reports anything else — compound specifiers such as `(integer 0 10)`, `(or …)`, struct names — as `unsupported-standard`, so a type system we do not model stays silent instead of answering a confident NIL. `COUNT` takes two arguments only; keyword arguments are not supported anywhere in the evaluator. Numbers are JS doubles, so `INTEGER` is `Number.isInteger` and `1.0` reads as `1`.*
  *Deferred: `loop`, `defstruct`, `handler-case`, multiple values, hash tables, `#+`/`#-`, backquote/unquote. All are in the standard-symbols list, so they are silently skipped rather than misreported. That list is now true: the twenty-one names it still held that were already implemented — `APPLY`, `BUTLAST`, `CHAR`, `CHAR=`, `CHAR-UPCASE`, `COUNT`, `DECF`, `DEFVAR`, `EQ`, `EQL`, `EQUALP`, `ERROR`, `EVENP`, `FUNCALL`, `INCF`, `MAKE-ARRAY`, `NUMBERP`, `ODDP`, `SCHAR`, `VECTOR`, `ZEROP` — were removed, taking it from 217 names to 196. For calls nothing changed, because `scopes.ts` fills the function table from `builtins` before `STANDARD_SYMBOLS`; the only visible effect is that a bare `do`, `case`, `incf`, `decf` or `defvar` used as a variable now reports `unbound-variable` instead of being dropped as our own gap. The corpus still reports the same 10 diagnostics.*
- **M4 — Value tracking.** Evaluate to a point, expose symbol values for inline display.
  *Status: complete except for the extension-side presentation and cache. Four pieces exist. `src/core/print.ts` renders a value as text the way SBCL would for the same limits — `(1 2 3)`, `(1 . 2)`, `#(1 2)`, `#<builtin CAR>`, `#<function F>`, `NIL` — with `...` for cut elements and cycles and `#` for cut depth (39 unit tests, 8 pipeline tests). `withStepCeiling` gives each pass its own ceiling under a fixed 2,000,000 backstop, so the value pass runs at 200,000 steps and an analysis pass at the backstop, with no shared mutable limit and no nesting. `src/core/bindings.ts` runs the file and records a binding snapshot when each list form finishes, with the binding map copied; `recordBindings` returns the snapshots plus an `unavailable` code (`budget`, `truncated`, `unparsed`), and `snapshotAt` resolves an offset to the innermost snapshot containing it, falling back to the latest finished form only when the run completed (24 tests). `src/core/hints.ts` turns a run into displayable hints: `collectHints` returns `hintsForLine`, `hintsInLines` and `hintAt`, and `formatHint`/`formatLine` render `X = 5` (19 tests).*
  *How hints behave, and why. A hint exists where a name is **read** and the run has a value for it. The list of reads comes from the same scope walk the static checker uses, so function heads, binding sites, quoted data, vector contents and the bodies of unmodelled standard forms are already excluded; the value comes from the snapshot containing that use, not from the line, which is what makes a function body show the parameter of the most recent call. One hint per name per line, at its first use, in source order. The line that binds a name — `(defparameter x 5)` — produces no hint for `X`, because it is a binding site; the next line that reads it does. Names absent from the snapshot are silent, so unbound names and builtins never appear. Values are printed with `printValue` at the same limits a REPL uses (8 elements, depth 3), overridable per call and provisional until the hint line has been seen with real values in it. Hints are therefore a report on what executed, and the static checker in M4-STATIC is the report on what will run; neither pretends to be the other.*
  *Measured limits, from the 41-file corpus and awaiting user testing. Only 7 of 41 files produce any hint at all (2 to 11 lines each), because most learner files define functions and call none of them, so no body ever runs — the same shape that motivated M4-STATIC. Inside a function that was never called, the only names with values are globals, and they show the state at definition time rather than at the line. A value read after a mutation in the same form can be stale (`incf` on the line shows the pre-increment value), because snapshots copy binding maps but not the mutable values inside them. Cost is not a concern: a full-file hint pass plus a query for every line takes about 4 ms on a 20 KB file.*
  *Rejected: a static tier for values. A constant-folding or symbolic tier was measured before building it — 35 of 77 corpus local bindings have literal values, 11 more are computable from literals, and the remaining 31 depend on inputs, while all 286 function parameters have no static value by definition. So a tier would restate what the source already says (`y = 5` beside `(let ((y 5))`), cover none of the parameters, and appear inconsistently next to hints from execution — a pattern a learner cannot explain without knowing scope and closure rules they are still learning. Values stay a runtime observation; if users later ask to see a binding's definition, that is a hover, not a per-line value.*
  *Remaining: the setting that switches between per-line hints and cursor position (a UI decision, extension-side), and caching one run per document version so a cursor move resolves against it instead of re-evaluating.*
- **M4-STATIC — Static checks over the whole file.** Every form checked whether or not anything calls it: the names each scope binds, undefined functions, argument counts, a variable called as a function, unbound variables, and structural checks inside bodies.
  *Status: complete as scoped — 44 scope tests and 49 name-check tests. Slices 1–3 are done: the scope model and symbol table (`src/core/scopes.ts`), structure rules for the walk (head atoms, `cond` clauses, `function` targets, `loop` clauses), and name checks over every body (`src/core/name-checks.ts`) — undefined functions, unbound variables, wrong argument counts, a variable called as a function. `analyze` runs them after the shape checks and evaluation, and drops the evaluator's copies of those three codes. Slices 4–6 decode the standard forms whose binding syntax used to be skipped: `defstruct` (its generated constructor, predicate, copier and accessors), `do`/`do*` and the `case` family, and the binding macros (`with-output-to-string`, `with-input-from-string`, `with-open-file`, `with-open-stream`, `with-hash-table-iterator`, `multiple-value-bind`, `destructuring-bind`, `handler-case`). Exists because learner code is usually a set of `defun`s loaded and compiled in the SBCL REPL rather than called in the file: 21 of the 37 corpus files with `defun`s call none of them, and 78 of 199 corpus `defun`s are never called. Evaluation only sees code that runs, so those bodies are checked today for nothing but name and arglist shape. This is the project's pre-compile promise — finding the mistake before SBCL's debugger does. The decodings for `do`/`do*` and the `case` family are now evaluated too, so those bodies trace; `defstruct` and the binding macros are still checker-side only, which is why tree-lab traces fail until `defstruct` is implemented in the evaluator (see `HANDOFF.md`).*
  *Remaining opaque forms, decoded only when learner code uses them: `defclass`, `defgeneric`, `defmethod`, `defmacro`, `deftype`, `defpackage`, `with-slots`, `with-accessors`, `multiple-value-setq`, `handler-bind`, `restart-case`, `macrolet`, `symbol-macrolet`. Their bodies go unchecked and, for the definition forms, their generated names are unknown. Name checks also need the checker's own list of special forms, so that `(if …)` is not read as a call to `IF`; that list mirrors the interpreter's dispatcher, and a test asserts the two stay in step. Evaluating `loop` is not part of this; it would need a milestone of its own.*
  *Deferred: any knowledge beyond this file and the standard library (unknown names stay at most a warning); unused bindings; type inference; finishing the `loop` walk (an atom in a driver position such as `xs` in `for x in xs`, and a bare-atom body such as `do x`, are skipped — recovering them means decoding clauses rather than scanning keywords; both are lost checks, not false reports); evaluating `loop` (5 of 38 files when measured, 10 occurrences — the corpus has since grown to 41 — against 28 `dolist`/`dotimes`, which already work).*
- **M5 — Recursion trace.** Frame enter/exit recording, rendered as a call tree outside the REPL.
  *Status: complete in core. Slice 5.1 records: `src/core/trace.ts` (`traceCalls`, `traceFormIn`, `TraceFrame`, `TraceResult`) runs in an observer and builds a tree of the calls made. No interpreter changes were needed — `applyFunction` already fires `onCallEnter`/`onCallExit`, and builtins bypass that path, so the trace holds the learner's own functions and never `+`, `car` or `list`. Arguments and results are printed at call time rather than at render time, so a cons mutated later cannot rewrite history; a frame that threw carries `error` and no `result`, while its ancestors carry neither because they never returned. Caps: 200,000 steps (the same as the value pass), depth 64 and 1,000 frames; past a cap evaluation continues so results still complete, recording stops, and `truncated` says so. `unavailable` reports `budget` or `unparsed`; `failed` reports the code of a non-budget error that ended the run. Slice 5.2 renders: `renderTrace` writes one line per frame as `NAME(args) => result`, two spaces of indent per level, `!! code` on the frame that threw, and `…` footers for a budget stop, a failure, or truncation. Slice 5.3 finds the calls to trace: `src/core/trace-cases.ts` (`traceCases`, `TraceCase`) scans line comments for the marker `;;[trace]` followed by one form — whitespace and case inside the brackets are tolerated, `;; [trace]` works, and a marker inside a block comment is ignored. Each marked line is an independent case: the file is re-evaluated in a fresh environment for that case, then the marked expression is traced in it, so two markers above one `defun` give two traces and one case cannot see another's mutations. Text after a marker that does not parse is reported as `unreadable` rather than silently dropped; a case whose call fails reports through the trace's own `failed`/`unavailable`. Slice 5.4 renders for a learner rather than as a step log: `renderTrace(result, options?)` labels the outermost call `root: 0:` and every entry line at the deepest level `max depth: n:`, leaves the levels between them bare, and closes with a summary line (`15 calls · max depth: 6 · final value: 5`). `TraceResult.finalValue` carries the value the run returned — the last top-level form's for a whole file, the marked form's for a case — and is omitted when the run failed. A cap or a budget stop makes the recorded depth a floor, so the label and the summary both read `(limit reached)`. The display limit this roadmap had specified is now delivered: `options.limit` (default 10) keeps the first N calls at each level plus the last one and states `… k more calls hidden`, `"all"` shows everything, and N is clamped to the 1,000-frame cap; a marker may also ask for it as `;;[trace:N]` / `;;[trace:all]`. `EXPLAIN_TRACE` is the explanation paragraph, appended only when `options.explain` is set, so the extension can style it or turn it into a setting. All four slices are 60 tests (39 trace, 21 trace-cases).*
  *Why the marker exists: learner files define functions and call none of them — a trace needs a call. On the corpus that is literal: without a marker, **0 of 41 files** produce a single frame. Writing the call in a comment lets the learner trace a function without editing what SBCL loads, and without a REPL: `;;[trace] (fact 4)` above the definition yields `root: 0: FACT(4) => 24` with each recursive call indented beneath its caller and the deepest level labelled. Measured limits: 0.2–1.2 ms for a call like `(fact 4)`; naive `(fib 15)` is 1,973 calls and hits the 1,000-frame cap in ~7 ms; `(fib 20)` is 21,891 calls and also trips the step ceiling in ~16 ms; `(fib 30)` would be 2,692,537 calls, so the caps turn it into `truncated`/`budget` instead of a several-second stall.*
  *Not recorded: call-site positions, because the observer does not carry them and adding them would touch the evaluator's hot path for a field the tree does not need yet. Not supported: a case spanning several comment lines, and a marker that is not a line comment. Rendering is text only; a tree view, hover hints about the marker, and live updating belong to M6. A counting mode (call totals and maximum depth with no frames kept) is the answer for calls too large to record and is deferred.*
  *Deliberate difference from SBCL's layout, not a defect to fix. SBCL prints a call as an entry line, then its subtree, then a `FUNC returned value` line at the same depth, so a call and its result are two lines and the result sits below what produced it. Our renderer keeps one line per call, `NAME(args) => result`, which means the value is attached to the call that produced it rather than printed on exit: a line reads "called with these arguments; everything below it totals this". The ordering of lines is unchanged (depth-first, as recorded); what differs is that a line is a labelled subtree rather than an event in time, so completion order is not shown. Against the same `count-atoms` call on `'(a (b (c d)) e)` that is 15 lines plus a summary where SBCL needs 30. Two labels make the ends of the recursion explicit — `root: 0:` on the outermost call, `max depth: n:` on every entry line at the deepest level — because following a recursion by eye is the thing learners struggle with, and the summary line states the call count, the depth and the final value in one place. Measured divergence worth keeping in mind: SBCL cannot trace a `labels` local at all (`COUNT-SUBTREE-SINGLE-CHILDREN is undefined, not tracing`), while our recorder sees it, which is what makes the corpus tree labs traceable at all; matching SBCL's wording is therefore never the goal, only its clarity.*
- **M6 — Extension glue.** `activate()`, diagnostics provider, view. The only layer importing `vscode`. The extension lives in this repo rather than a separate package, and the core stays free of `vscode` imports so it can be tested without the editor.

## Long-term / optional

- **M7 — Prettier-style formatter for Lisp.** Automated, opinionated re-indentation and layout of Common Lisp source. Optional; only after M1–M6 are complete.
- **Benchmarks.** After M1–M6, a benchmark pass to put numbers on parse and evaluate cost (file size vs. time), so design tradeoffs have evidence rather than intuition.
